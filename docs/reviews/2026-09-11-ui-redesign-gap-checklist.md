## 9. 建议落地顺序

> **决策记录（2026-09-11 已拍板，设计稿已同步）**：
> 1. **信息架构：采用侧边栏**（App.tsx 视图路由需迁移，最大单笔代码改动）。
> 2. **对子自动策略：按桌开关为主 + 「全部应用」批量按钮**（设计稿已改为「按桌」口径）。
> 3. **账本：砍掉余额列与自动对账**，定位为纯事件流水（设计稿已删余额投影相关元素）；「下注时 EV / 期望盈利 / 实际结果」列已补进设计稿，与代码 ledger 列对齐。
> 4. **UNKNOWN 与预留敞口：拆分为两枚独立 KPI**（总览/账本页均已改：预留敞口 RESERVED 蓝色、UNKNOWN 敞口红色+待勾销提示）。
> 5. **厅房切换 chip：确认要做**（数据源 platform-catalog 已有，需新增 UI 与筛选联动；第一期单扩展连接时 chip 仅作展示）。

1. **零差距直接对齐**：KPI 净盈亏、待加入牌桌、受控下注、保活开关、UNKNOWN 勾销文案、EV 分档/注额设置、版本号——设计稿即现状的形态升级。
2. **小改动（数据已有，缺投影/视图）**：限额占用进度、状态分布、事件流卡片、审计筛选、账本补三列、分桌 TopN、市场基线展示。
3. **中改动（需新接口/组件）**：收益走势图、珠盘路子组件（含对子/通对/和局标记）、四市场 EV 面板、风控聚合页、侧边栏 IA 迁移（若决策 A）。
4. **待产品决策后再动**：IA 形态（Tab vs 侧边栏）、对子策略全局 vs 按桌、余额投影与自动对账、UNKNOWN 与预留敞口 KPI 拆分、厅房切换 chip。
