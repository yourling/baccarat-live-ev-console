# Dafabet/mstrom 集成核对指南（非资金）

本指南仅用于核对构建、扩展连接、房间/牌桌数据导出、受控执行门禁和影子/模拟行为。**截至 2026-08-27，工程链路已完成 P0 加固，但当前仍没有获批的真实资金验收流程；不得将本指南、`live` 开关、无人值守恢复或浏览器执行器视为资金使用许可。**

## 当前实现边界

当前 Dafabet/mstrom 实现包含两条不同的请求路径：

- `BetIntent`/单次下注只接受 `bankerPair`（庄对）和 `playerPair`（闲对）。它经过 `TableActor`、`RiskManager`、reservation、牌靴/连接/下注窗口检查和按桌/靴/局/市场防重。
- `OperationalWager` 供桌面端四个手动按钮及庄/闲保活调度使用，支持 `banker`（庄）、`player`（闲）、`bankerPair` 和 `playerPair`。它也经过 `TableActor`、全局风控、reservation、回执审计、结算和按桌/靴/局/市场/来源防重。

所有真实请求要求实体牌靴、已连接投影、当前下注窗口、未封靴、无 `UNKNOWN` 敞口和无跨局结算缺口。浏览器端还会核对唯一 Dafabet 百家樂弹窗、唯一匹配桌台 iframe、会话 live gate、桌号/局号、平台玩法状态、限额、余额和未确认筹码。标准庄/闲结算按庄赢净利 `0.95`、闲赢净利 `1`、和局 push 处理，对子按桌台赔率配置结算。

## 生成核对包

在仓库根目录执行：

```powershell
npm run build
npm test
npm run package:desktop:win
```

核对程序位于 `apps/desktop/release`。解压版会在 `win-unpacked/resources/browser-extension` 附带浏览器扩展；使用 portable `.exe` 时，可从相邻解压版目录或 `apps/browser-extension` 加载开发扩展。

## 非资金集成核对

1. 在 Chrome 或 Edge 的扩展管理页开启开发者模式，加载浏览器扩展目录。
2. 启动桌面中控台；它会在 `127.0.0.1:17890` 启动本地桥。
3. 保持桌面端执行模式为 `shadow` 或 `simulated`，保持 `liveBetEnabled=false`，不要运行 `liveOn`，不要开启全局自动投注保活。
4. 在隔离、非资金的测试环境中打开一个 Dafabet/mstrom 百家樂页面，并在中控台中选择目标桌台。
5. 确认实时事件进入监控列表；验证桌号、局号、牌靴状态、连接状态和下注窗口的展示会随页面数据更新。
6. 观察影子/模拟记录、断线通知、阻断原因、持久事故和恢复提示；不要点击四市场手动下注按钮，也不要执行单次 `BetIntent`。
7. 关闭桌面窗口，确认进程、桥接、监控和调度仍保持；再次启动应用，确认隐藏窗口恢复。真正退出并重启进程后，已批准桌台必须先显示 `process-restarted` 断线/运行阻断，不能直接沿用旧连接状态。

预期结果：

- 页面、扩展和桥接连接后，桌台持续接收实时事件，数据可由 `BridgeRoomMonitor`/`TableExport` 导出。
- 整个核对过程中不应发送 `betRequest` 或 `OperationalWager` 执行请求，不应调用平台 `confirmBet`。
- 桥接只接受固定扩展 ID/token、恰好一个扩展连接和连续的会话消息序号；认证失败、断开、会话变化或序号缺口都应进入阻断。
- 断线后只有 `cursor-v1:<64 lowercase hex>`、严格连续的下一事件，或明确 `physical-shoe` 新靴重置才能恢复导出；页面的 `sessionAction: recovered` 不能单独恢复执行。
- 监控附着失败会按 2s / 5s / 15s / 30s（封顶）继续重试；页面三次快速恢复失败后会按 1m / 5m / 15m / 30m（封顶）继续监督。
- 诊断日志只保留脱敏 URL、长度和数量，不应出现正文、HTML、token、cookie 或原始网络载荷。

## 已暂停：真实资金验收

此前的“最小金额真实验证”步骤不再有效，也不在本仓库中提供操作指引。代码层 P0 已完成，但真实资金验收仍被以下外部发布条件阻塞：

- 对打包程序执行独立的真实站点、非资金长稳验收，覆盖持续采集、牌靴切换、会话过期、扩展重启、桌面进程重启、断网、数据过期和恢复。
- 用真实站点观察数据核对每局牌面、对子 EV 输入、下注窗口、结算结果与收益统计，确认不存在解析漂移或漏结算。
- 对固定扩展身份/token、消息序号、严格连续性证明、诊断脱敏、事故持久化和失败关闭行为形成可审计验收记录。
- 完成产品/安全发布审批、适用法律与平台条款确认，并获得独立的真实资金授权。

在这些条件全部完成前，结论仍是“工程上具备无人值守候选能力，运营上未获准无人值守真实资金运行”。

## 当前回执与记录说明

`ACCEPTED`、`REJECTED` 和 `UNKNOWN` 是执行回执状态，不等同于财务结算证明。`ACCEPTED` reservation 必须等待同桌/同靴/同局 `handSettled` 才形成 `realizedPnl`；庄/闲根据牌面点数和和局 push 规则结算，对子根据 `outcomes` 结算。

`UNKNOWN` 保留 reservation 风险敞口，立即关闭保活、撤销运行授权并阻断所有后续执行；新一局出现上一局仍为 `RESERVED` 的记录时会生成 `settlement-gap` 事故并失败关闭。不得自动清除、释放或重试这些状态。

验收记录只保存必要的桌号、牌靴 ID、局号、市场、时间、状态、reservation/receipt 标识和脱敏错误摘要。不要把密码、cookie、令牌或完整网络包纳入验收材料。
