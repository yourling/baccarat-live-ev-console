# mstrom 牌面解析实施蓝图(第二阶段综合)

> 本文是 20 路并行子代理研究的最终综合。逐路报告见 `.tmp-mstrom/card-research/`(01~20 号 md + scratch 脚本),原始数据 `.tmp-mstrom/chunk-01~28.log` 与 465MB `.tmp-mstrom/app-console.log`。
> 状态标记:【实证】=hex 级可复现;【推测】=待判别。

## 0. 一页结论

1. **协议模型重写**:载荷不是自定义 TLV,而是 **protobuf 线格式**(type2 广播帧 96.9% 完整消费);type3 周期状态帧为自定义二进制体。帧头实为 `[u16 type][u16 x16][u32 totalLength@4][u32 rawHeaderSeq@8]`——旧记录把长度/序号位置写反,且**不存在校验字段**。当前生产解析器硬校验 type 白名单、totalLength 自洽和桌台键；tick 单调性只属于研究观察，不是 `parseMstromFrame` 的硬门控。【实证:#05/#07/#08】
2. **结果编码已破译**:珠盘历史每手一条 LEB128 varint,g0 低 3 位=闲赢/庄赢/和(严格互斥),g1=赢家点数×2,bit5⟺庄赢7点;G串公式定案,每条记录可打绝对局号。【实证:#10】
3. **分数与阶段已 100% 可用**:protobuf f4=庄分/f5=闲分(varint);阶段 f3=1下注/2停注/0开牌;f10[0]=结果码 01庄/02闲/03和(6286/6286)。【实证:#02/#04/#19】
4. **跨游戏牌编码已实证**:卡字节 = suit<<4 | rank(suit 0-3 / rank 1..13=A..K),龙虎 18/18、ZJH/LBAC/NN 全吻合;BJ 暗牌=`ff01`。【实证:#05】
5. **百家乐(BAC)牌面不从 x1016.f10 生成**：后续 P0-0/P0-1 已证明 f10 尾部是赢家侧派生特征码，不是单张牌。生产 `cardObserved` 只读取页面自身已解码的 `GameStore.gameSnapshot.pcard/bcard`，不使用视觉/OCR。【实证:P0-0/P0-1 + runtime hook】
6. **已知牌面样本的帧可以找回**:GT-06(SL/SZ)在 app-console.log 已金额九市场逐项精确匹配定位,GT-04 U2 批次共现锚定——**在这些窗口重跑字节搜索**是当前成本最低的破译路径(P0-0)。【实证:#01】

## 1. 协议地面真相 v2(替代 roadmap 第一阶段记录)

### 1.1 帧结构
- type=2 广播:桌键 ASCII + 游戏类型后缀 + protobuf 消息(×2806)
- type=3 状态:桌键4B + 游戏码(BAC/ROU/…) + 自定义状态体(×3427)
- type=0/4/32/258/37356:心跳/系统/加密面(合计<4%)【实证 #20】
- x16(type2)=schema 选择器:0x1016 局广播 / 0x1008 路子更新 / 0x2017 BJ / 0x2016 NN·SG / 0x400a 小更新(成对镜像需去重)【实证 #05/#17】
- 无校验和:≈330 组合穷举在 2812 数据帧上命中≤1(噪声)；历史所称 `u16@10 tick` 是 `rawHeaderSeq@8` 的低半部，不是额外头字段【实证 #08】
- `rawHeaderSeq` 只保留原始字段语义，不能等同桥接层 `sourceSeq`，也不能直接宣称为全局可信连续序号；捕获层 28/32 个 chunk 有 dropped 标记 + 28 处跨块撕裂【实证 #20】

### 1.2 type3 状态体(原「字段8」)
- 11B 头 + f64 靴累计额 + u8 N + N×12B 市场记录 [u16 市场ID][u16 下注笔数][IEEE754 BE double];ID 升序,键恒 4B,长度=20+12N(295/295);洗牌期 N=0
- BAC 市场 ID 共 14 个:0x01庄/0x02闲/0x03和【实证】;0x04/05 推测庄对/闲对、0x0b 龙宝、0x0f 大小【推测 #18】
- 旧「[43 00 00] 头」「变长4-5B键」「21→33→57→65 重建」均为 TLV 错位伪影;增量全是市场记录,**字段8 内无牌面(排除)**【实证 #18/#19/#04】
- 旧「0x41/0x42 状态哈希」= protobuf 键字节伪影;真摘要=fixed64 7B,市场冻结时仍翻转→可作开牌触发器【实证 #09】

### 1.4 结果/路子编码(#10,本阶段最大收获)
- 字段3(x1008.f7 / 快照)= 当前靴逐局珠盘史,每手追加 1 条 LEB128 varint(2-5B);7bit 组分解 g0 | g1<<7 | g2<<14:
  - g0.bit0/bit1/bit2 = 闲赢/庄赢/和(严格互斥,3770 条零违例;频率 46.6/43.5/9.7% ≈ 理论)
  - g1 = 赢家最终点数×2(P 赢全偶且无 0 点;和局分布与全枚举模拟一致)
  - bit5 ⟺ 庄赢且点=7(1638/1638);bit3/bit4(~7.5%)疑闲对/庄对(顺序未定);bit6 仅闲赢点≥4
  - 置信度:结果位+点数≈95%,对子归属≈60%
- 双时钟标定:x1008.f2w0=该桌累计手数(Δf2==Δ记录锁步);G串尾缀=f2−每桌常数(18 桌偏移 100% 一致)→ 每条记录可打绝对局号;GUI 两位局号=去"1"尾缀
- 同骨架旁证:龙虎 g1=2×牌点(2..26)、轮盘字节=0..36 口袋号
- ⚠️ 结算滞后(#01-A):G串先切下一局、状态帧金额延续才清零——对齐必须用 f3=0 结算簇/金额清零,不能用后缀跳变(否则系统性错位一局)
